# 客户端架构

## 1. 设计目标

客户端需要在同一连接上处理连接管理、登录、商品浏览、购票、订单、退票和通知。
这些任务共享会话和页面状态，但来源不同：

- 用户操作来自 Swing EDT。
- 网络帧来自读线程。
- 定时操作来自协议和心跳线程。

如果所有逻辑都直接写入页面类，业务状态、网络线程和 Swing 组件会互相耦合。
因此客户端采用页面、任务插槽、协议、网络和状态五层结构。

## 2. 分层

```text
ui/
  ScreenView / MainFrame / SwingUiPort

任务层
  LongTaskRuntime / ClientTask / tasks/

状态层
  AppState / AppEvent / TaskContext

协议层
  ProtocolWorker / ProtocolData

网络层
  NetworkClient
```

## 3. 出站链路

```text
用户点击控件
  -> ScreenView 创建 AppEvent
  -> FrontendSlot.submit
  -> LongTaskRuntime.events
  -> 对应 ClientTask
  -> ProtocolWorker.request
  -> NetworkClient.outbound
  -> writer thread
  -> 长度帧
  -> TCP
```

Swing EDT 只提交事件，不等待网络，也不执行协议解析。

## 4. 入站链路

```text
TCP
  -> reader thread
  -> 完整帧
  -> AppEvent.WIRE
  -> LongTaskRuntime
  -> ProtocolWorker
  -> SERVER_RESPONSE / REQUEST_TIMEOUT
  -> ClientTask
  -> AppState
  -> ComponentWorker
  -> Swing EDT
```

网络读线程不直接修改业务状态。协议匹配和任务处理在明确的线程所有权下完成。

## 5. 线程和队列

| 组件 | 线程或队列 | 容量与行为 |
| --- | --- | --- |
| Swing EDT | UI 事件线程 | 不执行阻塞网络操作 |
| `LongTaskRuntime` | 单任务线程 | 2048 事件，满时丢弃并记录 |
| `NetworkClient` reader | 阻塞读 | 精确读取 4 字节头和正文 |
| `NetworkClient` writer | 阻塞写 | 1024 出站队列，满时发送失败 |
| `ProtocolWorker` | 单线程调度器 | 待处理请求 60 秒超时 |
| 心跳 | writer 空闲 30 秒 | 自动发送 `ping|` |

读线程和写线程分开，避免入站解析和出站发送互相等待。心跳由写线程发送，避免
多个线程同时写同一个 socket。

## 6. 请求匹配

协议没有请求 ID，`ProtocolWorker` 使用本地请求 ID 和响应命令维护映射：

```text
普通请求:
  register -> register
  catalog.list -> catalog

两阶段请求:
  order.reserve -> reserve -> reserve.result
  refund.submit -> refund -> refund.result
```

收到 `queued` 后不会结束任务，而是把同一请求重新登记到后续结果命令。收到最终
结果、早失败或超时才结束任务。

## 7. 状态管理

`AppState` 保存：

- 连接状态。
- 当前会话和 token。
- 用户身份。
- 商品列表和当前选择。
- 订单列表和当前选择。
- 当前页面。
- 各任务状态和提示。

页面读取不可变 `Snapshot`。长任务线程负责写入状态，组件更新通过
`ComponentWorker` 切回 EDT。

## 8. 导航

导航由 `NavigationService` 统一管理。业务任务决定何时跳转，页面只提交导航事件。

固定页面标识：

```text
connection
login
catalog
buy
orders
refund
log
```

这样页面切换和业务流程可以分开演进。新增页面不需要在网络层或协议层增加分支。

## 9. 任务插槽

| 任务 | 处理内容 |
| --- | --- |
| `ConnectionTask` | 建连、断连、网络错误 |
| `AuthTask` | 注册、挑战登录、登出、身份查询 |
| `CatalogTask` | 商品列表和票种选择 |
| `ReserveTask` | 购票受理和最终结果 |
| `OrderTask` | 个人订单和单订单查询 |
| `RefundTask` | 退票受理和最终结果 |
| `NavigationTask` | 页面导航校验 |

`LongTaskRuntime` 遍历任务，由 `ClientTask.accepts` 决定事件归属。每个任务通过
`TaskContext` 使用共享网络、协议和状态接口。

## 10. 扩展方法

新增功能时按以下顺序修改：

1. 数据模型。
2. `AppState` 状态和快照。
3. 新页面 `ScreenView`。
4. `MainFrame` 页面注册。
5. `NavigationService` 页面标识。
6. 新 `ClientTask`。
7. `TicketClientApp` 任务注册。
8. 端到端验证。

约束：

- 页面不直接使用 `NetworkClient`。
- 任务不直接操作 Swing 控件。
- 网络线程不直接修改 `AppState`。
- 两阶段请求必须处理 `queued`、最终成功和最终失败。
- 共享业务状态放在 `AppState`，不要塞进页面字段。

## 11. 当前限制

- 阻塞 Socket，不是 NIO。
- 队列满时当前策略是拒绝新事件或返回发送失败，没有自动重试窗口。
- 协议没有请求 ID，只能依赖命令和顺序映射。
- 没有 TLS。
- token 不持久化，客户端重启后需要重新登录。
