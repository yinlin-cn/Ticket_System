# 通信协议与数据模型

## 1. 传输

- TCP。
- 默认端口 `9101`。
- 正文使用 UTF-8。
- 单帧正文最大 `9999` 字节。

## 2. 帧格式

每帧由 4 位 ASCII 十进制长度头和正文组成：

```text
<4 位十进制 UTF-8 正文字节数><UTF-8 正文>
```

示例：

```text
0005ping|
0007pong|ok
```

读取规则：

1. 精确读取 4 字节长度头。
2. 按十进制解析正文字节数。
3. 精确读取对应字节数。
4. 不能把一次 `read()` 当作一帧。
5. 不能只按换行符切分。

## 3. 命令编码

普通命令使用 `|` 分隔参数，末尾带 `|`：

```text
order.reserve|<token>|<ticket_type_id>|<quantity>|<idempotency_key>
```

`catalog` 和 `order.my` 的正文可以包含多行，但仍属于同一个协议帧。

## 4. 命令清单

```text
ping|
register|<username>|<password>
login|<username>|<password>
login.challenge|<username>
login.proof|<username>|<proof_hex>
logout|
whoami|
catalog.list|
order.reserve|<token>|<ticket_type_id>|<quantity>|<idempotency_key>
order.status|<token>|<order_no>
order.my|<token>
refund.submit|<token>|<order_no>|<quantity>|<idempotency_key>|<ticket_type_id>
notice.push|<identity_id>|<message>
```

购票、退票和订单查询保留 `token` 参数。当前连接已经登录时 token 可以为空，例如：

```text
order.reserve||1001|1|client-key-1
```

连接身份优先；只有连接没有身份且 `TICKET_TOKEN_FALLBACK=1` 时才使用 token。

## 5. 参数限制

| 参数 | 约束 |
| --- | --- |
| 用户名 | 3 到 32 个字符 |
| 注册密码 | 6 到 64 个字符 |
| 购票数量 | 1 到 10 |
| 退票数量 | 1 到 10，且不超过可退数量 |
| 幂等键 | 非空，不超过 64 字节 |
| 单帧正文 | 最多 9999 字节 |

## 6. 接口

### 6.1 心跳

```text
ping|
pong|ok
```

### 6.2 注册

请求：

```text
register|alice|secret123
```

成功：

```text
register|ok|alice
```

### 6.3 旧版登录

```text
login|alice|secret123
login|ok|<token>|<user_id>
```

该方式会直接传输密码，只用于兼容。

### 6.4 挑战式登录

第一步：

```text
login.challenge|alice
login.challenge|ok|<nonce_hex>|<salt_hex>
```

客户端计算：

```text
key   = PBKDF2-HMAC-SHA256(password, salt, 120000, 256)
proof = HMAC-SHA256(key, nonce)
```

其中 `salt` 和 `nonce` 必须先按十六进制解码为原始字节。

第二步：

```text
login.proof|alice|<proof_hex>
login.proof|ok|<token>|<user_id>
```

### 6.5 当前身份和登出

```text
whoami|
whoami|ok|<identity_id>|<username>|<virtual_fd>

logout|
logout|ok
```

### 6.6 商品列表

```text
catalog.list|
```

成功：

```text
catalog|ok
<ticket_type_id>|<event_name>|<ticket_name>|<price_cents>|<remaining>
...
```

### 6.7 购票

请求：

```text
order.reserve|<token>|<ticket_type_id>|<quantity>|<idempotency_key>
```

受理：

```text
reserve|queued|<order_no>|accepted
```

最终成功：

```text
reserve.result|ok|<order_no>|<amount_cents>|PENDING_PAY|created
```

最终失败：

```text
reserve.result|error|<order_no>|<code>|<reason>
```

早失败可能直接返回：

```text
reserve|error|<code>|<reason>
```

`queued` 不表示落库成功。客户端必须继续等待 `reserve.result`。

### 6.8 订单状态

```text
order.status|<token>|<order_no>
```

成功：

```text
order.status|ok|<order_no>|<ticket_type_id>|<quantity>|<amount_cents>|<status>|<refunded_qty>
```

### 6.9 个人订单

```text
order.my|<token>
```

成功：

```text
order.my|ok|<count>
<order_no>|<ticket_type_id>|<quantity>|<amount_cents>|<status>|<refunded_qty>|<created_at>
...
```

### 6.10 退票

请求：

```text
refund.submit|<token>|<order_no>|<quantity>|<idempotency_key>|<ticket_type_id>
```

受理：

```text
refund|queued|<refund_no>|<order_no>|accepted
```

最终成功：

```text
refund.result|ok|<refund_no>|<order_no>|<quantity>|<status>|<remaining_stock>
```

最终失败：

```text
refund.result|error|<refund_no>|<order_no>|<code>|<detail>
```

### 6.11 定向通知

请求：

```text
notice.push|<identity_id>|<message>
```

调用结果：

```text
notice.push|ok|<identity_id>|<1|0>
```

目标在线时收到：

```text
notice|<sender_username>|<message>
```

## 7. 两阶段状态语义

```text
order.reserve
  -> reserve|queued
  -> reserve.result|ok
  或 reserve.result|error
  或 reserve|error

refund.submit
  -> refund|queued
  -> refund.result|ok
  或 refund.result|error
  或 refund.submit|error
```

客户端必须同时处理三类情况：

1. 先受理，后最终成功。
2. 先受理，后最终失败。
3. 未受理，直接早失败。

## 8. 订单状态

```text
PENDING_PAY
PAID
PARTIALLY_REFUNDED
REFUNDED
CANCELLED
EXPIRED
```

当前系统创建订单后状态为 `PENDING_PAY`，退款成功后进入部分退款或全额退款状态。
支付、取消和过期流程目前是预留状态，没有完整业务实现。

## 9. 错误响应

普通错误：

```text
<command>|error|<code>|<message>
```

购票最终错误：

```text
reserve.result|error|<order_no>|<code>|<reason>
```

退票最终错误：

```text
refund.result|error|<refund_no>|<order_no>|<code>|<detail>
```

主要错误码：

| 类别 | 错误码 |
| --- | --- |
| 协议和参数 | `BAD_REQUEST`、`UNKNOWN_COMMAND`、`BAD_USERNAME`、`BAD_PASSWORD`、`BAD_QUANTITY`、`BAD_TICKET_TYPE`、`BAD_IDEMPOTENCY_KEY`、`BAD_ORDER`、`BAD_TARGET` |
| 鉴权 | `UNAUTHORIZED`、`BAD_CREDENTIALS`、`ACCOUNT_LOCKED`、`ALREADY_ONLINE`、`CHALLENGE_EXPIRED`、`BAD_PROOF`、`NO_CONNECTION` |
| 账号 | `USER_EXISTS`、`BAD_USER`、`REGISTER_FAILED`、`TOKEN_ERROR`、`CRYPTO_ERROR` |
| 库存与准入 | `SOLD_OUT`、`DUPLICATE`、`NOT_READY`、`REDIS_ERROR` |
| 订单与退款 | `NOT_FOUND`、`NOT_OWNER`、`TICKET_TYPE_MISMATCH`、`STATUS_INVALID`、`EXCEED_REFUNDABLE` |
| 服务端 | `SERVER_BUSY`、`BAD_PRICE`、`DB_ERROR`、`INTERNAL` |

## 10. MariaDB 数据模型

### `ticket_users`

| 字段 | 说明 |
| --- | --- |
| `id` | 用户主键，也是账号身份 ID |
| `username` | 唯一用户名 |
| `password_hash` | PBKDF2 结果十六进制 |
| `password_salt` | 随机盐十六进制 |
| `login_fail_count` | 连续失败次数 |
| `lock_until` | 临时锁定截止时间 |

### `ticket_inventory`

| 字段 | 说明 |
| --- | --- |
| `ticket_type_id` | 票种主键 |
| `event_name` | 活动名 |
| `ticket_name` | 票名 |
| `price_cents` | 单价，单位分 |
| `total_qty` | 总库存 |
| `remaining_qty` | 最终剩余库存 |

### `ticket_orders`

| 字段 | 说明 |
| --- | --- |
| `order_no` | 业务订单号，唯一 |
| `user_id` | 用户 ID |
| `ticket_type_id` | 票种 |
| `quantity` | 购买数量 |
| `refunded_qty` | 已退款数量 |
| `amount_cents` | 总金额，单位分 |
| `status` | 订单状态 |
| `idempotency_key` | 用户请求幂等键 |

唯一约束：

```text
(order_no)
(user_id, idempotency_key)
```

### `ticket_refunds`

| 字段 | 说明 |
| --- | --- |
| `refund_no` | 退款业务号，唯一 |
| `original_order_no` | 原订单号 |
| `user_id` | 用户 ID |
| `ticket_type_id` | 票种 |
| `quantity` | 退款数量 |
| `request_id` | 用户退款请求幂等键 |

唯一约束：

```text
(refund_no)
(user_id, request_id)
```

## 11. Redis 数据

| 键 | 内容 |
| --- | --- |
| `ticket:stock:<ticket_type_id>` | 当前允许继续进入数据库事务的票数 |
| `ticket:idem:<user_id>:<idempotency_key>` | 幂等键到订单号的映射 |

Redis 键由服务端启动时从 MariaDB 初始化。`init_redis.sh` 会删除演示幂等键，
只应在隔离环境执行。
