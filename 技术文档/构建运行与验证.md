# 构建运行与验证

## 1. 组件

| 组件 | 推荐环境 |
| --- | --- |
| 服务端 | Ubuntu 或 WSL，C++20 |
| Java 客户端运行 | Windows 10/11 x64，使用自带运行时的发布包 |
| Java 客户端构建 | Windows 10/11 x64，JDK 17+ |
| MariaDB | 本地或网络可达 |
| Redis | 本地或网络可达 |

## 2. 服务端依赖

在 Ubuntu、Debian 或 WSL 的服务端源码目录执行：

```bash
bash scripts/install_deps.sh
```

脚本会安装并检查：

- C++20 编译器。
- CMake 3.20+。
- OpenSSL 开发库。
- hiredis 开发库。
- MariaDB Connector/C 开发库。
- MariaDB Server 和客户端。
- Redis Server 和 `redis-cli`。

脚本可重复执行，不会修改数据库或票务数据。若软件源缺少对应包，会在结束前列出
仍然缺失的依赖。等价的 Debian/Ubuntu 软件包为：

```text
build-essential cmake pkg-config libssl-dev libmariadb-dev libhiredis-dev
mariadb-server mariadb-client redis-server redis-tools
```

## 3. 创建数据库和用户

`scripts/init_db.sh` 会自动完成以下工作：

- 使用管理员权限创建 `chat` 数据库。
- 创建 `chat@localhost` 和 `chat@127.0.0.1` 两个本地开发账号。
- 使用 `ALTER USER` 把可能存在的 `unix_socket` 认证改为密码认证。
- 授予 `chat.*` 权限，再使用 `chat/chat123` 通过 TCP 登录。
- 执行 `db/init.sql` 创建表并写入演示数据。

手工排查时使用的等价 SQL：

```sql
CREATE DATABASE IF NOT EXISTS chat
  CHARACTER SET utf8mb4
  COLLATE utf8mb4_unicode_ci;

CREATE USER IF NOT EXISTS 'chat'@'localhost' IDENTIFIED BY 'chat123';
CREATE USER IF NOT EXISTS 'chat'@'127.0.0.1' IDENTIFIED BY 'chat123';
ALTER USER 'chat'@'localhost' IDENTIFIED BY 'chat123';
ALTER USER 'chat'@'127.0.0.1' IDENTIFIED BY 'chat123';

GRANT ALL PRIVILEGES ON chat.* TO 'chat'@'localhost';
GRANT ALL PRIVILEGES ON chat.* TO 'chat'@'127.0.0.1';
FLUSH PRIVILEGES;
```

脚本从普通用户运行时会在需要时调用 `sudo`。如果 MariaDB 原本使用
`unix_socket` 认证，只执行 `CREATE USER IF NOT EXISTS` 不会修改已有账号，因此
脚本会继续执行 `ALTER USER`，避免 `ERROR 1698`。

## 4. 初始化服务端

在 WSL 中进入服务端源码目录：

```bash
sudo service mariadb start
sudo service redis-server start
redis-cli ping
```

预期返回：

```text
PONG
```

初始化、构建和启动：

```bash
bash scripts/init_db.sh
bash scripts/init_redis.sh
bash scripts/build.sh
bash scripts/run_server.sh
```

成功启动后输出：

```text
ticket server listening on 0.0.0.0:9101
```

构建产物位于 `build/ticket_server`。

## 5. 启动客户端

### 5.1 免 JDK 运行

目标电脑没有安装 JDK 或 JRE 时，不在目标电脑上编译源码，而是在构建电脑上
进入 `客户端/源代码` 执行：

```bat
package.bat
```

脚本通过 JDK 自带的 `jpackage` 生成 Windows x64 应用镜像，包内 `runtime/`
目录包含客户端所需的最小 Java 运行时。生成文件为：

```text
release/TicketClient/TicketClient.exe
release/TicketClient-Windows-x64.zip
```

目标电脑只需解压 ZIP 并双击 `TicketClient.exe`，不需要安装 JDK/JRE，也不需要
配置 `JAVA_HOME` 或 `PATH`。也可以从交付包根目录双击
`客户端/安装及启动脚本/启动免JDK客户端.bat`。

发布包只能运行在构建时对应的操作系统和 CPU 架构上。当前脚本面向 Windows
x64；每次重新打包后都应完整复制整个 `TicketClient` 目录，不能只复制
`TicketClient.exe`，否则会缺少 `runtime/` 和 `app/`。

### 5.2 从源码运行

构建电脑在 Windows 中进入客户端源码目录：

```bat
build.bat
run.bat
```

也可以直接双击 `客户端/安装及启动脚本/启动客户端.bat`。启动入口每次都会
删除旧的 `out/`，以 Java 17 为目标版本重新编译，再启动
`ticketslots.TicketClientApp`。WSL 或 Linux 图形终端可使用：

```bash
cd 客户端/源代码
chmod +x build.sh run.sh
./run.sh
```

检查 JDK：

```bat
java -version
javac -version
```

两个命令都必须能执行，版本均不得低于 17。只安装 JRE、`JAVA_HOME` 指向旧
JDK，或直接把 `ui/tasks` 子包当作主类启动，都会导致无法构造或启动。

源码构建和免 JDK 发布包是两条不同路径：前者要求构建电脑安装完整 JDK，后者
要求交付整个应用目录，但如果只在本机运行已生成的应用，则不再依赖系统 Java。

如果服务端运行在 WSL，Windows 客户端通常可以直接连接 `127.0.0.1:9101`。
如果服务端位于另一台机器，应在连接页面填写服务端 IP。

IDE 配置：

- Source Root 设置为 `客户端/源代码/src`。
- Project SDK 和 Language Level 使用 JDK 17 或更高版本。
- Main Class 设置为 `ticketslots.TicketClientApp`。
- Working Directory 设置为 `客户端/源代码`。

## 6. 基本验证流程

1. 启动 MariaDB 和 Redis。
2. 启动服务端。
3. 启动客户端。
4. 在连接页面连接 `127.0.0.1:9101`。
5. 注册临时账号并登录。
6. 刷新商品列表。
7. 选择票种和数量提交购票。
8. 确认先出现受理状态，再收到最终结果。
9. 刷新个人订单。
10. 对订单执行部分退款或全额退款。
11. 再次刷新订单和商品库存。

正确结果应满足：

```text
成功购票数量 + 最终库存 = 初始库存
已退款数量不超过订单购买数量
订单状态与退款数量一致
```

## 7. 配置

### 7.1 Redis 与鉴权

| 环境变量 | 默认值 | 说明 |
| --- | --- | --- |
| `TICKET_REDIS_HOST` | `127.0.0.1` | Redis 地址 |
| `TICKET_REDIS_PORT` | `6379` | Redis 端口 |
| `TICKET_REDIS_TIMEOUT_MS` | `1000` | Redis 超时 |
| `TICKET_ADMISSION_REDIS` | `1` | 是否启用前置准入 |
| `TICKET_TOKEN_FALLBACK` | `1` | 是否允许 token 兜底 |

关闭 Redis 准入：

```bash
TICKET_ADMISSION_REDIS=0 bash scripts/run_server.sh
```

### 7.2 订单数据库

| 环境变量 | 默认值 |
| --- | --- |
| `TICKET_DB_HOST` | `127.0.0.1` |
| `TICKET_DB_PORT` | `3306` |
| `TICKET_DB_USER` | `chat` |
| `TICKET_DB_PASSWORD` | `chat123` |
| `TICKET_DB_NAME` | `chat` |
| `TICKET_ORDER_DB_CONNECTIONS` | `8` |
| `TICKET_ORDER_DB_WORKERS` | `6` |
| `TICKET_ORDER_BATCH_MAX` | `500` |
| `TICKET_ORDER_TICK_MS` | `2` |

框架查询数据库参数当前在 `app/main.cpp` 中配置。

## 8. 常见问题

### `NOT_READY`

Redis 中没有库存键。检查 Redis 是否启动，并在演示环境重新执行
`scripts/init_redis.sh`。

### `REDIS_ERROR`

检查 Redis 地址、端口、超时和服务状态。

### `ALREADY_ONLINE`

同一账号已经有一条在线业务连接。登出旧连接或等待心跳超时。

### 客户端一直等待

检查：

- 是否按 4 字节长度头读取。
- 是否收到 `queued` 后继续等待 `.result`。
- 是否发生早失败但任务仍在等待后续响应。
- 是否触发 60 秒请求超时。

### 数据库连接失败

检查：

- `chat` 用户是否允许从 `127.0.0.1` 登录。
- `init_db.sh` 是否执行。
- 框架 DB 参数和 `TICKET_DB_*` 是否一致。
- MariaDB 最大连接数是否足够。

如果出现 `ERROR 1698 (28000): Access denied for user 'chat'@'localhost'`，重新
执行：

```bash
bash scripts/init_db.sh
```

脚本会修正已有的 `chat` 账号认证方式，并用密码重新验证 TCP 登录。

## 9. 验证范围说明

本精简包不包含压力测试脚本和历史实验代码。当前包用于交付最终模块、演示完整
业务链路和说明架构。

需要做容量测试时，建议单独建立隔离测试目录，并至少记录：

- 并发连接数和总请求数。
- 成功、售罄、重复和错误数量。
- QPS 及持续时间。
- CPU、内存、数据库连接和 Redis 指标。
- 初始库存、成功票数、最终库存、订单数和退款数。

只观察 QPS 而不检查订单与库存守恒，不能证明抢票链路正确。
